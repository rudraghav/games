# Feature kickoff

1. Orient: agent guidance, latest progress, PRD, app flow, owning architecture/UI/rules doc.
2. Record the outcome, constraints, entities, rules, visibility and observable acceptance.
3. Define boundaries and typed API/engine contracts before implementation.
4. Implement producer, persistence, projection and UI together. Reuse existing primitives.
5. Run affected verification groups and exercise the actual workflow in a browser.
6. Update owning README, source-of-truth docs and root progress with evidence and gaps.

New games enter through registry metadata plus an independent engine and renderer.
All launch games must satisfy the same release gate; a catalogue tile is not a
completed game. No source, schema, deployment or credential is shared with Shikha.
